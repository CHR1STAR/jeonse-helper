# 전세계약 도우미

전월세 계약이 처음인 사람이 매물을 비교하고, 계약 준비부터 계약 후 할 일까지 차근차근 확인하는 모바일 웹앱입니다.

- [웹앱 시연](https://jeonse-helper.onrender.com)
- [프로젝트 개발 기록](https://velog.io/@christar)

## 실행 방법

비회원 기능은 `index.html`을 브라우저에서 열어 살펴볼 수 있습니다. **비회원으로 계속하기 → 확인 → 매물 등록** 순서로 진행하세요. 사진 파일은 `index.html`과 같은 폴더에 둡니다. 로그인은 HTTP 또는 HTTPS 주소에서 실행하고 [로그인 설정](login-setup.md)을 완료해야 합니다.

Docker가 설치된 환경에서는 저장소 최상단에서 실행합니다.

```sh
docker build -t jeonse-helper .
docker run --rm -p 127.0.0.1:8080:80 jeonse-helper
```

`http://localhost:8080`에서 열 수 있습니다. 공개 배포에서는 Render가 이 Dockerfile로 웹 UI를 실행하며, 로그인 및 데이터 저장은 외부 Supabase가 담당합니다.

## 시연 순서

1. 집 이름, 계약 유형, 보증금 등을 한 질문씩 입력해 후보를 등록합니다. 모르는 항목은 건너뛸 수 있습니다.
2. 후보 목록에서 집을 골라 수압, 누수, 벌레 등 방문 체크리스트를 기록합니다. 결과와 메모는 매물별로 저장됩니다.
3. **이 집으로 계약할게요**를 눌러 계약 전 질문을 진행합니다. 화면을 나갔다 돌아오면 저장한 단계에서 이어갈 수 있습니다.
4. 계약을 완료하고 계약 후 할 일을 확인합니다. 계약 준비 중에는 등기사항증명서 사진에서 주요 용어를 찾는 한글 OCR 기능도 시연할 수 있습니다. OCR 모델 파일 다운로드에는 인터넷 연결이 필요합니다.

## 저장 구조 및 제출 점검

비회원 기록은 브라우저에 저장됩니다. 로그인 상태에서는 다음 테이블을 사용합니다.

| 테이블 | 역할 |
| --- | --- |
| `jeonse_workspaces` | 계정별 작업 공간과 저장 버전. 이전 앱에서 사용하던 저장 데이터도 유지 |
| `jeonse_listings` | 작업 공간에 속한 매물과 표시 순서 |
| `jeonse_visit_checks` | 각 매물에 속한 방문 점검 항목과 결과 |

작업 공간 하나에 매물이 여러 개, 매물 하나에 점검 결과가 여러 개 연결됩니다. 저장할 때 같은 DB 거래에서 관련 테이블이 함께 갱신되며, 새 앱은 매물과 점검을 두 테이블에서 읽어 화면에 표시합니다. Supabase는 로그인한 사람이 자기 기록만 조회할 수 있도록 제한합니다.

새 환경에서는 [기본 스키마](jeonse-supabase.sql)에 이어 [매물·점검 마이그레이션](001-listings-and-visit-checks.sql)을 실행합니다. 기존 환경에서는 마이그레이션만 실행하고, 성공한 후 새 앱을 배포합니다.

| 항목 | 현재 상태 |
| --- | --- |
| 매물 입력과 목록 | 구현. 비회원 시연 가능 |
| 계정 로그인과 기록 동기화 | Google·이메일 로그인 코드와 SQL 포함. 공급자 설정과 실제 로그인 검증 필요 |
| 웹앱 Docker 실행 | Nginx 컨테이너로 실행. 인증과 DB는 외부 Supabase 사용 |
| 자동 테스트 | 비회원 브라우저 흐름과 PostgreSQL 저장·격리 검증 |

## 자동 테스트

GitHub의 **Actions → Project checks**에서 자동 검사 결과를 확인할 수 있습니다. 브라우저 검사는 매물 등록, 매물별 체크 상태, 새로고침, 계약 준비 이어하기를 확인합니다. DB 검사는 임시 PostgreSQL에서 이전 데이터 이전, 저장 및 삭제 반영, 계정 사이의 데이터 격리를 확인합니다.
